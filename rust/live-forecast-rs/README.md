# live-forecast-rs

Rust port of `shared/live-forecast.ts`, bridged with napi-rs. Generated by rust-anything;
`src/port.rs` delegates to `relay_core::shared::live_forecast`, and `src/port/args.rs` turns the
bindings' JSON (`undefined` members, `{"$num": ...}` markers) into the relay-core types.

## Functions

- `liveForecast` (`shared/live-forecast.ts:197`)

`liveSetup` stays in TypeScript here (`js_only`): its result carries the demand function. Its
port, `live_forecast::live_setup`, is checked by the ported unit tests
(`crates/relay-core/tests/live_forecast.rs`) and through `liveForecast`, which simulates it.

## Output shape

An outage segment is `{ accountId: undefined, from, to }` in the TS, a key that holds
`undefined`; relay-core leaves the key out (`JSON.stringify` writes both the same).
`src/port/segments.rs` puts it back for the comparison.

## Loop

Cases are the calls the planning tests make. Generated inputs are off (`--count 0`): they pass
arbitrary JSON where the TS types name a `DayPlan` and a `PlanContext`.
