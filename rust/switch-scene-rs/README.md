# switch-scene-rs

Rust port of `shared/switch-scene.ts`, bridged with napi-rs. Generated by rust-anything;
`src/port.rs` delegates to `relay_core::shared::switch_scene`, and `src/port/args.rs` turns the
bindings' JSON (`undefined` members, `{"$num": ...}` markers) into the relay-core types.

## Functions

- `sceneDeadline` (`shared/switch-scene.ts:52`)
- `switchWindowVisible` (`shared/switch-scene.ts:202`)

`pickDisguise`, `switchScene`, `sceneLine` and `sceneView` take functions, and the `SwitchStory`
class has an accessor, so they stay in TypeScript here (`js_only`). Their ports
(`switch_scene::{pick_disguise, switch_scene, scene_line, scene_view, SwitchStory}`) are checked by
the ported unit tests, `crates/relay-core/tests/switch_scene.rs`.

## Loop

Cases are the calls the tests make plus `inputs.jsonl` (every stage with every outcome, and every
window state with and without a view). Generated inputs are off (`--count 0`): they pass arbitrary
JSON where the TS types name `SwitchSceneState`. The original module has a TypeScript parameter
property, which Node's type stripping refuses, so the recorder loads it through tsx.

```sh
rust-anything record rust/switch-scene-rs --count 0 --pin-clock \
  --node-arg=--import=$PWD/node_modules/tsx/dist/loader.mjs --inputs rust/switch-scene-rs/inputs.jsonl \
  --from-tests -- node --import tsx --test tests/switch-scene.test.ts tests/switch-stage.test.ts
rust-anything build rust/switch-scene-rs
rust-anything diff rust/switch-scene-rs
rust-anything gate rust/switch-scene-rs
```
