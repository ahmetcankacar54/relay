# usage-rollups-rs

Rust port of `shared/usage-rollups.ts`, bridged with napi-rs. Generated by rust-anything;
`src/port.rs` delegates to `relay_core::shared::usage_rollups`, and `src/port/args.rs` turns the
bindings' JSON (`undefined` members, `{"$num": ...}` markers) into the relay-core types.

## Functions

- `emptyRollups` (`shared/usage-rollups.ts:39`)
- `hourKey` (`shared/usage-rollups.ts:47`): relay-core answers `""` where `toISOString` throws;
  the port raises the TS `RangeError` there.
- `validWindow` (`shared/usage-rollups.ts:52`)
- `sameReset` (`shared/usage-rollups.ts:60`)
- `foldSample` (`shared/usage-rollups.ts:161`)
- `foldSamples` (`shared/usage-rollups.ts:239`)
- `catchUp` (`shared/usage-rollups.ts:252`)

`foldSample` and `catchUp` name the rollups `rollups` (the TS `r` clashes with the generated wire
reader).

## Known differences

- Two `foldSamples`/`catchUp` test cases pass a sample with an explicit `resetsAt: undefined`; the
  TS keeps that key in `last`, relay-core cannot hold an `undefined` member. The key is invisible
  in JSON (`rollups.json` is the same).
- relay-core's `Date.parse` reads ISO 8601 and RFC 2822 only, not V8's legacy fallback
  (`Date.parse("key_name-1")` is a date in V8): `sameReset` inputs are realistic dates.

## Loop

Cases are the calls the tests make plus `inputs.jsonl`: generated `hourKey` times (any number is
valid) and realistic `sameReset` pairs around the two-minute tolerance. Generated inputs are off
otherwise (`--count 0`): they pass arbitrary JSON where the TS types name `UsageSample` and
`UsageRollups`.

  --inputs rust/usage-rollups-rs/inputs.jsonl --from-tests -- node --import tsx --test \
