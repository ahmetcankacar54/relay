# adaptive-plan-rs

Rust port of `shared/adaptive-plan.ts`, bridged with napi-rs. Generated by rust-anything;
`src/port.rs` delegates to `relay_core::shared::adaptive_plan`, and `src/port/args.rs` turns the
bindings' JSON (`undefined` members, `{"$num": ...}` markers) into the relay-core types.

## Functions

- `plannedRate` (`shared/adaptive-plan.ts:132`)
- `paceFactor` (`shared/adaptive-plan.ts:157`)
- `todaysPace` (`shared/adaptive-plan.ts:182`)
- `nextStartCandidates` (`shared/adaptive-plan.ts:238`)
- `replanStarts` (`shared/adaptive-plan.ts:264`): a `schedule` carried in the input is read
  and ignored, as in the TS.

## Output shape

An outage segment is `{ accountId: undefined, from, to }` in the TS, a key that holds
`undefined`; relay-core leaves the key out (`JSON.stringify` writes both the same).
`src/port/segments.rs` puts it back for the comparison.

## Loop

Cases are the calls the pace and replan tests make. Generated inputs are off (`--count 0`):
they pass arbitrary JSON where the TS types name a `Tempo`, `UsageSample`s and a `DayPlan`.

```sh

  --import tsx --test tests/adaptive-pace.test.ts tests/adaptive-replan.test.ts \
  tests/adaptive-schedule.test.ts tests/window-keeper.test.ts
```
