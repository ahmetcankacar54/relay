# day-plan-rs

Rust port of `shared/day-plan.ts`, bridged with napi-rs. Generated by rust-anything; `src/port.rs`
delegates to `relay_core::shared::day_plan`, and `src/port/args.rs` turns the bindings' JSON
(`undefined` members, `{"$num": ...}` markers) into the relay-core types.

- `planContext` (`shared/day-plan.ts:57`)
- `cyclePhases` (`shared/day-plan.ts:71`)
- `clearPlanCache` (`shared/day-plan.ts:144`)
- `planCacheStats` (`shared/day-plan.ts:150`): the optimization count of this process's plan cache.
- `dayPlan` (`shared/day-plan.ts:234`)
- `shouldHaveWindow` (`shared/day-plan.ts:308`)
- `nextPlannedStart` (`shared/day-plan.ts:323`)

The re-exports from `shared/work-hours.ts` (`workInterval`, `shiftDate`, `isWeekend`, `dayStart`)
are checked in that unit.

## Output shape

The TS writes `undefined` into two keys that relay-core leaves out (`JSON.stringify` writes both
the same): a day without hours is `{ date, interval: undefined, accounts }`, and an outage
segment is `{ accountId: undefined, from, to }`. `src/port.rs` and `src/port/segments.rs` put
those keys back for the comparison.
