# widget-snapshot-rs

Rust port of `shared/widget-snapshot.ts`, bridged with napi-rs. Generated by rust-anything;
`src/port.rs` delegates to `relay_core::shared::widget_snapshot` (`crates/relay-core`) and reads
the arguments with `rust/parity-args`. `overviewAccounts` (`src/data/selectors.ts`), which the
snapshot ranks the other accounts with, is ported there too (`widget_snapshot::overview_accounts`).

## Functions

- `widgetMood` (`shared/widget-snapshot.ts:112`)
- `widgetCountdown` (`shared/widget-snapshot.ts:294`)
- `buildWidgetSnapshot` (`shared/widget-snapshot.ts:340`): key order is compared, since the
  result is what `widget/today.json` holds.
- `widgetVisibleKey` (`shared/widget-snapshot.ts:683`)

## Known differences

An invalid IANA time zone makes the TS throw (`RangeError: Invalid time zone specified`), while
relay-core reads an unknown zone as UTC (store validation never lets one through); the cases use
real zones.

## Loop

Cases are the calls the tests make plus `inputs.jsonl` (the accounts fixture in every locale and
five zones, the scan's percent, the week's hit counts, no active account, estimated costs, an
Antigravity account, and countdown edges). Generated inputs are off (`--count 0`): they are not
`TokenToday`s, accounts or settings.

```sh
rust-anything record rust/widget-snapshot-rs --count 0 --pin-clock --inputs rust/widget-snapshot-rs/inputs.jsonl \
  --from-tests -- node --import tsx --test tests/widget-snapshot.test.ts
rust-anything build rust/widget-snapshot-rs
rust-anything diff rust/widget-snapshot-rs
rust-anything gate rust/widget-snapshot-rs
```
