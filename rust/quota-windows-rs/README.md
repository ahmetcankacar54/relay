# quota-windows-rs

Rust port of `shared/quota-windows.ts`, bridged with napi-rs. Generated by rust-anything;
`src/port.rs` delegates to `relay_core::shared::quota_windows` (`crates/relay-core`) and reads the
arguments with `rust/parity-args`. The TS takes `Pick<AccountUsage, ...>`: only the picked fields
are read, over an otherwise empty `AccountUsage`. `quotaWindows` and `spentModelWindows` return
the caller's own window objects; `usedPercent` crosses as a JS number (NaN included).

## Loop

Cases come from `inputs.jsonl` (five-hour × weekly windows incl. NaN/±Infinity/-0, passed and
unparsable resets, model-only pools in both period orders, `Pick` shapes) plus the calls the tests
make; generated inputs are off (`--count 0`) because they are not usage readings.

Known representational difference (31 cases): the TS `limitHeadline` literal always has a
`resetsAt` key, `undefined` when the window has none; relay-core's struct omits it. The two are
the same JSON; the diff tells them apart.

```sh
rust-anything record rust/quota-windows-rs --count 0 --pin-clock --inputs rust/quota-windows-rs/inputs.jsonl \
  --from-tests -- node --import tsx --test tests/limit-headline.test.ts tests/limit-origin.test.ts tests/model-limits-ui.test.ts
rust-anything build rust/quota-windows-rs
rust-anything diff rust/quota-windows-rs
rust-anything gate rust/quota-windows-rs
```
